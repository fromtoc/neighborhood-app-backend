本次更新三大重點：1) 所有 API 回傳頭像 URL、2) 垃圾車即時追蹤 API、3) 個人資料 API 調整。

1. 大頭貼（avatarUrl）全面上線 新增

所有回傳用戶資訊的 API 現在都帶有 avatarUrl 欄位。遵循 useAvatar 設定：用戶明確關閉頭像時回傳 null，否則回傳 Firebase 社群登入的大頭貼 URL。

1.1 PostResponse（貼文列表 / 貼文詳情）

欄位型別說明
authorAvatarUrlString | null貼文作者大頭貼，null 表示無頭像或已關閉
{
  "id": 23442,
  "authorName": "超管",
  "authorAvatarUrl": "https://lh3.googleusercontent.com/...",  // 新增
  "authorRole": "SUPER_ADMIN",
  "authorBadge": "埔南里里長",
  ...
}

影響 API：

  • GET /api/v1/posts?neighborhoodId=&type=&scope=&page=&size=
  • GET /api/v1/posts/{id}
  • GET /api/v1/posts/info?neighborhoodId=&scope=&page=&size=

1.2 PostCommentResponse（留言 / 回覆）

欄位型別說明
avatarUrlString | null留言者大頭貼
{
  "id": 501,
  "nickname": "張里長",
  "avatarUrl": "https://lh3.googleusercontent.com/...",  // 新增
  "content": "@張里長 jj",
  "likeCount": 0,
  "liked": false,
  ...
}

影響 API：

  • GET /api/v1/posts/{postId}/comments?page=&size=
  • GET /api/v1/posts/{postId}/comments/{commentId}
  • GET /api/v1/posts/{postId}/comments/{commentId}/thread?page=&size=

1.5 Mention 候選人

GET /api/v1/users/mention-candidates?neighborhoodId=&scope= 回傳的 avatarUrl 現在也遵循 useAvatar 設定（之前可能回傳已關閉頭像的 URL）。

1.6 用戶個人頁

GET /api/v1/users/{userId} 和 GET /api/v1/users/me 回傳的 avatarUrl 同樣遵循 useAvatar。

App 端處理建議：
  • avatarUrl 為 null 時顯示首字母頭像（取 nickname 或 authorName 的第一個字）
  • avatarUrl 非 null 時用 URL 載入圖片，建議加快取（URL 通常為 Google / Facebook / LINE 的 CDN）
  • 圖片載入失敗時 fallback 到首字母頭像

2. 垃圾車即時追蹤 API 新增

目前支援桃園市清潔車即時定位。後端每 15 秒從 Node 爬蟲同步車輛位置，App 可輪詢取得最新資料。所有端點 permitAll，無需登入。

2.1 取得指定里範圍內的垃圾車

GET /api/v1/garbage-trucks?neighborhoodId={id}&radiusMeters={500}
參數必填預設說明
neighborhoodId是—里 ID，用來取得里中心座標
radiusMeters否500搜尋半徑（公尺）

回傳：

{
  "code": 200,
  "data": {
    "trucks": [
      {
        "carId": "桃園-清-001",
        "lat": 24.9936,
        "lng": 121.3010,
        "carType": "垃圾車",          // 垃圾車 / 資源回收車
        "addr": "桃園區中山路100號",   // 目前位置描述
        "cleanStatus": "收運中",       // 收運狀態
        "status": "行駛中"             // 車輛狀態
      }
    ],
    "count": 1,
    "center": { "lat": 24.9936, "lng": 121.3010 },
    "neighborhood": "埔南里",
    "city": "桃園市",
    "district": "桃園區",
    "lastUpdate": "2026-03-21T02:00:15.123"
  }
}

2.2 取得所有垃圾車（地圖模式）

GET /api/v1/garbage-trucks/all

回傳所有車輛（不限範圍），適合全地圖顯示。

{
  "code": 200,
  "data": {
    "trucks": [ ... ],  // 同上格式
    "count": 87,
    "lastUpdate": "2026-03-21T02:00:15.123"
  }
}

2.3 取得里邊界 GeoJSON

GET /api/v1/garbage-trucks/boundary?neighborhoodId={id}

回傳里的行政區邊界 GeoJSON，用於在地圖上繪製里邊界多邊形。

{
  "code": 200,
  "data": {
    "geojson": "{\"type\":\"Polygon\",\"coordinates\":[[[121.30,24.99],...]]}",
    "neighborhoodId": 1234
  }
}
App 端使用建議：
  • 建議每 15~30 秒輪詢一次 /garbage-trucks?neighborhoodId=
  • 目前僅桃園市有資料，其他縣市的里查詢會回傳空陣列
  • lastUpdate 為空字串時表示爬蟲尚未同步到任何資料
  • geojson 為 null 時表示該里無邊界資料
  • 車輛 lat/lng 座標系為 WGS84（同 Google Maps）

3. 更新個人資料 — 支援 PATCH 變更

原本只支援 PUT，現在同時支援 PUT 和 PATCH，方便 App 端選擇。

PUT 或 PATCH /api/v1/users/me/profile
Authorization: Bearer {token}
Content-Type: application/json

{
  "nickname": "新暱稱",        // 選填
  "bio": "自我介紹",           // 選填
  "useAvatar": true             // 選填，是否顯示社群登入頭像
}
useAvatar 邏輯：
  • true 或 null（未設定）→ 所有 API 回傳 Firebase 社群登入的頭像 URL
  • false → 所有 API 回傳 avatarUrl: null，前端應顯示首字母頭像

4. 單則留言 API 支援 liked 狀態 變更

GET /api/v1/posts/{postId}/comments/{commentId}

之前：不回傳 liked（始終為 null）。

現在：帶 Authorization header 時回傳當前用戶的 liked 狀態（true/false）。

{
  "id": 501,
  "likeCount": 3,
  "liked": true,  // 之前可能為 null，現在帶 token 時會是 true/false
  ...
}
