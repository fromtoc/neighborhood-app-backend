Q1: FCM data payload 有帶 roomId 嗎？

有了。聊天通知的 FCM payload 現在包含 roomId：

{
  "notification": {
    "title": "張里長 在堵南里聊聊發了訊息",
    "body": "123"
  },
  "data": {
    "notifType": "chat",
    "refType": "chat_li",     // "chat_li" | "chat_district"
    "refId": "100",           // 最新訊息 ID
    "roomId": "5"             // ← 新增：聊天室 ID
  }
}

App 端收到 FCM 後可直接用 roomId 導航到對應聊天室，不需要用 refId 反查。

Q3: REST 發送訊息後會廣播到聊天室 topic 嗎？

現在會了。不管從 HTTP POST 還是 STOMP 發送，都會廣播：

App 發送訊息（兩種方式皆可） ├── STOMP: /app/chat.send/{roomId} ← 已有廣播 └── REST: POST /chat/rooms/{roomId}/messages ← 本次新增廣播 兩者都會： 1. 存入 DB（chat_message 表） 2. 更新 chat_room.last_message 3. 廣播到 /topic/rooms/{roomId} ← 所有訂閱者即時收到 4. 觸發通知（里聊/區聊/私聊） 5. 觸發 @ mention 通知

App 端建議架構

發送訊息： 優先用 STOMP /app/chat.send/{roomId} STOMP 斷線時 fallback 用 REST POST /chat/rooms/{roomId}/messages 接收訊息： 訂閱 STOMP /topic/rooms/{roomId} 收到新訊息 → 更新聊天畫面 + 呼叫 PUT /chat/rooms/{roomId}/read 通知更新： 訂閱 STOMP /topic/user/{userId} 收到 type="chat" → 用 roomId 判斷是否當前聊天室 是 → 自動已讀，不顯示通知 否 → 顯示通知 badge，刷新未讀數

Q4: 群聊有查詢成員名單的 API 嗎？

沒有。群聊不維護成員名單。通知是透過「關注里」機制推播：

聊天類型通知對象機制
里聊天關注該里的所有用戶user_neighborhood_follow 表 + user_notification_settings.chat=1
區聊天關注該區任一里的所有用戶查該區所有里 → 同上
私聊對方一個人直接推播

App 端不需要查成員名單，只需要：

  1. 訂閱 /topic/rooms/{roomId} 即時收訊息
  2. 後端自動推播 FCM + WebSocket 通知給所有關注的用戶
